# Documentation Suite

This directory is the specification and governance record for the platform: the module
specs, the cross-module journeys, the generated contracts, and the process the team runs
against — RFCs, plans, rulings, ledgers, research, closures and findings. The map below is
`document-ids.md` §1.4's layout; the family table is its §1.2. Neither is restated in
substance here — both are read directly, and this page names where they live.

## Map

```
docs/
├── README.md              the map: this tree and §1.2's table — nothing that goes stale
├── INDEX.md               generated — one row per id, rows and documents alike
├── REDIRECTS.csv          generated by the migration — every old path and old id → new id → new path
├── _templates/            one file per document family, header pre-filled
├── roadmap.md             phases (milestone sections), WK- and SL- rows, living
├── open-questions.md      OQ- mirror, living
```

without an `RFC-` and an `RL-` is a violation of that section, not a decision this page
makes.

## Reading order for a newcomer

1. `specs/00-overview.md` — context, module map, glossary.
2. `workflows/` — the shortest end-to-end story is a good second stop; `../INDEX.md`
   resolves which `WF-` id that is today.
3. The module spec you are about to work on.
4. `contracts/` for the exact shapes referenced by that spec.
5. `process/delivery-process.md` and `process/document-ids.md` for how the team executes
   against the specs and how every record here is identified.

## Checking the suite

```bash
python3 scripts/audit-docs.py
```

Verifies the specification suite's internal consistency — links, requirement-ID integrity,
open-question mirroring, ADRs, the ten-section spec standard, JSON Schema validity, and the
RFC-937 id-standard checks. The numbered list of what each check catches is the script's own
module docstring, kept current there (`.claude/skills/docs-audit`) rather than restated here.

```bash
python3 scripts/doc-id.py check
```

Validates every governed document's header against `document-ids.md` §1.5's field set and
the resolver's id rules — filename/id/directory agreement, no reused number, no bad
transition in `status:`.

```bash
python3 scripts/doc-index.py --check
```

Confirms `docs/INDEX.md`, the generated one-row-per-id index every citation resolves
against, is current. Regenerate it with `python3 scripts/doc-index.py` whenever a document
is added, renamed or its `status:` changes, and commit the result in the same change.

Run all three before committing a docs change.

## Conventions

- Requirement IDs are permanent: `FR-<MODULE>-<n>`, `NFR-<MODULE>-<n>`. Never renumber;
  append, or mark `SUPERSEDED BY <id>`.
- Every spec follows the 10-section standard in `CLAUDE.md` §5.
- Domain vocabulary comes from `CLAUDE.md` §7, restated authoritatively in
  `specs/00-overview.md` §2. New terms are added to the glossary **before** first use.
- Money in the rating path is integer minor units (pence) or `Decimal` — never float.
- Open design choices are recorded in `open-questions.md`, not silently resolved.
- Every id and status in this repository is one governed standard, `document-ids.md` — a
  new family, a new status word or a new directory is a change to that document, never a
  local convention invented in one corner of the tree.
