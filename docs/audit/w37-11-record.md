# W37-11 residue record

The governed per-(file, class) residue ceiling `scripts/_docverify.py`'s
`load_w37_11_record` reads (`W37_11_RECORD_PATH`). Population is the deputy's, filed one
entry at a time as W37-6's ruled DISCLOSE-with-residue rows are worked — never the code's,
and never invented ahead of the ruling that names it.

Each row: which file, which ruled row/check (`cls`) its count belongs to, the count itself,
a one-line reason it resisted the general migration mechanism, and its owner. A `cls` with
no row here is ungoverned — `check_residue_ceiling` compares nothing against it — so adding
this file's first row for a `cls` is what puts that ruled row under the ceiling; until then
its residue is measured but never gated.

**Re-keyed 2026-09-16 (PR-D1, W37-6 resume) from migrated path to control (pre-migration)
path.** A migrated path is a fact about the id allocation the run that produced it
computed, not about the file (handover 2026-09-06 §3 item 5); PR-A changes that
allocation, so a row keyed by migrated path stops resolving the moment the allocation it
was built under changes. Every `path` cell below is now the file's own pre-migration
path, resolved against a fresh `doc-id.py migrate --verify --ref f35cfe5` run's own
`docs/REDIRECTS.csv`, split into: 191 rows a real move resolves (`old_path != new_path`),
21 rows a same-path token-only redirect leaves unchanged (`old_path == new_path`), 196
rows resolved by identity (absent from `REDIRECTS.csv`, verified to exist unchanged at
that literal path in the migrated tree — the migration never moves them), and 3
path-independent `(no file named in message)` sentinel rows. `cls`, `count`, `reason` and
`owner` are byte-identical to the pre-re-key table — this changed only the key, never a
measurement.

**Loop 1 fix (same date): the key is `(control_path, cls)`, with a content-derived
`part_slug` suffix for a SPLIT source and an identity fallback for a MERGE target —
never a bare `(control_path, cls)` collapse.** The first re-key collapsed every migrated
file of a split source (one control document producing several migrated files — 74 rows
here) onto the identical `(control_path, cls)` key, silently discarding all but one row's
count at ceiling-build time and producing a false `RESIDUE_REGRESSION`/`RESIDUE_PROGRESSED`
pair on the very next `--verify` run. Fixed in `scripts/_docid.py`
(`part_slug`/`composite_control_key`/`resolve_to_control_paths`): a split source's part is
suffixed onto the control path with `#` (74 rows here, e.g.
`docs/plans/2026-09-01-nt-0016-q4-q5-q6-q7-notes-rulings.md#q4-the-ownership-matrix-...`);
a merge target (many control documents producing one migrated file — 6 rows here, all
`docs/findings/register.md`, fed by both `docs/audit/register.md` and
`docs/audit/phases/1b/register.md`) resolves to **itself** rather than an arbitrary pick
among its sources, deterministic regardless of `REDIRECTS.csv`'s row order. Verified: 0
duplicate `(path, cls)` keys across all 491 rows (predicate: every line starting with
`|` whose first cell is non-empty, not `path`, and not the `---` separator — pinned to the
header row's own shape, not a line number, per loop 1's finding that a header edit shifts
`NR`). `_docid.build_ceiling` now refuses (raises `AmbiguousResidueKeyError`, naming every
colliding row) rather than silently overwriting, should a future row collide again.
