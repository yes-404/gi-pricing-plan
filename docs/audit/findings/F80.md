# F80 — `migrate()` cannot complete on the real corpus today: the "Pending proposals" container has no discovery code, and the unconditional plan-reviews census is what catches it

Evidence essay for the register row self-named `(F80)` in `docs/audit/register.md`. Found
independently by the W37-5b auditor by running the code against the real tree, not
disclosed in any merged PR body.

## Provenance

Ruling 88 (`docs/plans/2026-09-02-w37-container-family-and-line-citations-rulings.md`, PR
#601) rules `docs/audit/plan-reviews.md`'s "Pending proposals" container `RFC-`,
`kind: process`, `status: closed`, as its own record. Ruling 89 §1 holds that stamping the
live document is "discharged during the run [W37-6], not before it" — correctly, per the
obligations list's own row 7, whose discharge criterion was only the derivation-and-ruling,
never the discovery code. Nobody has since checked what happens when `migrate()` reaches
this file without that code.

## The defect, verified directly at `3f41d60`

```
$ python3 -c "
import importlib.util, sys, pathlib
sys.path.insert(0, 'scripts')
spec = importlib.util.spec_from_file_location('doc_id', 'scripts/doc-id.py')
doc_id = importlib.util.module_from_spec(spec)
sys.modules['doc_id'] = doc_id
spec.loader.exec_module(doc_id)
ROOT = pathlib.Path('.').resolve()
doc_id._check_plan_reviews_heading_census(ROOT)
"
NotImplementedError: migrate: .../docs/audit/plan-reviews.md carries heading(s) the
census cannot classify as a record or as derived body: line 1155 ("### Pending
proposals — for the §14 review at W11's close (drafted 2026-08-29)"). Ruling 88
ruled their disposition (RFC-, kind: process) but this module has no code yet
that builds that draft -- implement that discovery before migrating this file.
```

The error message is the module's own — it names the exact gap. `_check_plan_reviews_heading_census`
is called **unconditionally** inside `migrate()` (`scripts/doc-id.py:3000`, immediately after
`review_drafts = _discover_plan_reviews(root)` at `:2991` and before the plain-plans and
requirements discovery that follow), not gated behind any zero-discovery branch the way
`_check_roadmap_not_silently_unrecognised` is (that one is genuinely conditional — calling it
directly and unconditionally, as an early draft of this same investigation did, produces a
false-alarm `NotImplementedError` that reflects a misuse of the function outside its documented
calling contract, not a real defect; its own docstring states plainly "called only from
`migrate`'s `roadmap_drafts` branch, so it never runs, and never raises, when discovery
succeeded"). The plan-reviews census carries no such gate. So a real `migrate()` run today
would raise at this exact point and never reach roadmap conversion, closure-records writing, or
anything after it.

## Why this is not one of the obligations list's 39 rows

Ruling 88 postdates the obligations list (`b648c22`) by several commits. The obligations
list's row 7 could not have anticipated a defect in a ruling that had not yet been made, and
its own discharge criterion for row 7 — a derivation, then a ruling — is fully met. This is a
new obligation, created the moment Ruling 88 landed, that nothing since has assigned to
anyone. Ruling 83's own obligation 1 is on point regardless: *"The census runs before W37-6,
not during it. Every unclassified unit is resolved and recorded ahead of the go-ahead."* This
is exactly such an unclassified unit, found only by running the census the ruling itself
required be built — the mechanism working as designed, on a target nobody had pointed it at
yet.

## Scope of this finding

- **Not fix-before-close for W37-5b as originally scoped** — group A is the eighteen rows
  the obligations list names, and this is not one of them. But it is squarely the *kind* of
  thing group A exists to catch: testable outside the run, on already-merged code, with no
  dependency on the migration having happened.
- **It does block W37-6's go-ahead as things stand.** A real `migrate()` invocation cannot
  get past this file today. Acceptance item 13's argument for W37-5b's own existence (§2.1
  of the slice decision: *"a slice whose acceptance standard cannot pass is not a slice that
  should be authorised"*) applies to this gap by the same reasoning, discovered one ruling
  later.
- **Proposed disposition** (a proposal; the verdict is the lead's): **not started**
  (`CLAUDE.md` §13) — discovery code that turns the "Pending proposals" heading into an
  `RFC-` draft, symmetric to what `d7c9b08`/`614c92c` already built for closure-records'
  `LG-` drafts. Owner not named here; candidates are the W37-6 executor (per Ruling 89's own
  "discharged during the run" framing) or a narrow W37-5b/W37-5c follow-up (per the same
  reasoning §2.1 of the slice decision used for row 9). Both are live options and the choice
  is the lead's, not derivable from anything on record.
- **Falsifiable**: discharged when the discovery code lands and `_check_plan_reviews_heading_census(ROOT)`
  returns cleanly against the real tree, or by a corrected reading showing some other call
  path resolves this heading before the census runs.

## A related, disclosed-but-unresolved collision, not filed separately

`scripts/doc-id.py`'s `migrate()` runs **two** independent guards over
`docs/audit/plan-reviews.md` in sequence — `_check_plan_reviews_heading_census` (`:3000`) and
`_check_headed_split_file_not_silently_unrecognised` (`:3001-3003`) — with a comment at the
call site stating this is deliberate and "reported to the lead as a collision rather than
silently reconciled" (PR #602's body). Both would raise on the same file for related reasons
today; which one actually surfaces first is immaterial to this finding (the pipeline halts
either way), so it is noted here rather than investigated further — it does not change F80's
disposition.
