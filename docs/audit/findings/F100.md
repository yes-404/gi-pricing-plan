# F100 — `_discover_findings`' docstring describes a citation rewrite the same file's code refuses to make, and writes a padded id to do it

**Filed 2026-09-03 at `e97b97a` by the decision-maker, on the lead's direction, out of
Ruling 103 §1.3.** Work item **W37-6**, phase 2.

**Id allocation, and the reservation that is not a reservation.** The lead's instruction was to
take **F98**, on the ground that F97 is reserved on unmerged PR #685. F98 is not free either.
Swept across **every** ref rather than `origin/main`:

```
for r in $(git branch -r | grep -v HEAD); do git grep -hoE '\bF[0-9]{2,3}\b' $r -- docs/; done \
  | grep -oE '[0-9]+' | sort -n -u | awk '$1>=95'          → 95 96 97 98 99
```

`origin/docs/f99-two-dot-diff-misread` carries F97, F98 and F99, and F99's own record says so:
*"`git grep` … at `7f19241` returns a maximum of **97**, which makes **F98 look free and it is
not** — F98 is allocated to the decision-maker on an unmerged branch."* **F97 is on `origin/main`
already**, so the number the warning protects is F98, not F97.

**And F98 has no artifact anywhere.** `git for-each-ref` over every local and remote ref, listing
each tree for a file named `F98.md`, returns nothing; its only occurrence in the repository is
that sentence in `F99.md`. **No decision-maker session in this window allocated it.** A
reservation whose only artifact is an assertion inside another record cannot be distinguished
from a lost allocation, and it blocks the number permanently, because every future allocator
reads the sentence and skips. **Raised with the lead; not resolved here.** This record takes
**F100**, verified free across every ref by the sweep above.

## The mechanism

`_discover_findings` (`scripts/doc-id.py:2716`) carries this in its docstring, at **`:2755-2758`**:

> *"The essay's own H1 still names the legacy `F<n>` token in its body text; that line is
> rewritten by the same global Phase D citation pass every other document's body goes through
> (`token_map["F84"] = "FD-00084"` reaches the file `_write_document_drafts` already wrote,
> exactly as it reaches every other citing file in the tree)."*

**Every load-bearing clause of that sentence is false, and the code that falsifies it is in the
same file.**

**First, `token_map["F84"]` is never set.** `token_map` has exactly two kinds of writer. The
**id** branch, `scripts/doc-id.py:5900-5901`:

```python
if d.old_token is not None and d.prefix != "FD":
    token_map[d.old_token] = canon
```

and the **path** branch, `token_map.update(_path_rewrite_tokens(old, new))` at `:5926`, `:5958`,
`:5965`, `:5981` and `:5998`. `:5901` is the only assignment in the file — `git grep -nE
'token_map\['` returns `:2757` (this docstring), `:4870` (a read inside `_rewrite_citations`) and
`:5901`. **`FD` is excluded from the id branch by the guard's own condition**, on the maintainer's
ruling quoted in the comment immediately above it (`:5885-5899`):

> *"The essays get ids and paths now; `F<n>` stays a resolver alias to W37-11."*

with the grounds stated there: W37-6's ambiguity sweep found the low end of the `F<n>` range
reused across independent, undated audit eras — *"`F12` alone names three"* — so a blanket
`\bF12\b` substitution would rewrite all three to whichever one a given run's F12 happens to be.

**Second, the value is the wrong form even for a family that were included.** `canon` is
`_docid.canonical(d.prefix, d.number)`, whose own docstring reads *"The citation form — NT-0019
§1.1 rule 2: unpadded, always"* and which returns `f"{prefix}-{n}"` (`scripts/_docid.py:104-108`).
The id branch can only ever write `FD-84`. `FD-00084` is `_docid.padded`'s output — the
**filename** form — standing in a citation position.

**Third, the two statements entered the tree together.** `git log --format='%h %s' -S'FD-00084' --
scripts/doc-id.py` and the same over `-S'same global Phase D citation pass'` both return
**`2f0467e`** (#671, *"implement the FD and WF document families"*) and nothing else. **This is
not drift.** Drift has a story — a guard added later, a docstring not updated with it. Here the
guard and the sentence contradicting it were written in one commit and have never been
reconciled by anyone, which is why no review caught it: there was no diff in which they appeared
as a change.

## Why this is a finding and not a typo

**It misleads a reader about behaviour, in the file that is the migration's engine.** A reader of
`_discover_findings` comes away believing finding-essay H1s are swept by the Phase D citation
pass. They are not, deliberately, on a maintainer's ruling — and the docstring is the only
narrative account of the FD family's discovery. The migration's most-read explanatory text says
the opposite of what the migration does.

**And it is independently an acceptance-row violation.** Ruling 103 §1.2 rules §7(e) as: a padded
id outside a filesystem path that resolves through `docs/INDEX.md` to a real governed thing.
`FD-00084` is padded; it is not in a path; and `FD-84` is a real governed thing — F84 is a
register finding. NT-0019 §1.1 rule 2 names **docstrings** in its no-exception list. **This is the
exemplar Ruling 103 §1.3 uses to refuse a document-keyed exemption for (e)**: `doc-id.py` would
sit at the top of any "self-documentation" exclusion list, and both defects would have survived
there untouched.

## What this is not

**Not a live code defect.** The code is correct and the guard is doing what it was ruled to do.
Nothing mis-migrates because of this.

**Not a claim that the migration should write `FD-84`.** It should write nothing for `F<n>` this
Work. `assigned` and `redirect_rows` still record the mapping (`:5884`, and `REDIRECTS.csv` per
NT-0019 §4 step 1), so W37-11's resolver has the data; only the prose sweep is held back.

**Not a finding against Ruling 103.** The ruling cites this line as evidence; the defect is in
`doc-id.py`.

## Reproduction — the mutation that must become detectable

**The falsifiable clause bites the docstring, not the guard.** A fix that changed `:5900`'s
condition to admit `FD` would make the docstring true and would reverse a maintainer's ruling;
that is the wrong direction and must not be how this closes.

**Discharged when** `_discover_findings`' docstring states what the guard actually does — that
`F<n>` is held out of the Phase D prose sweep this Work, with the mapping carried to W37-11 by
`REDIRECTS.csv` — **and** a reader of it cannot come away believing finding-essay H1s are
rewritten by that pass.

**The check that proves it, once §7(e) has an implementing predicate:** `FD-00084` at `:2757` is
named by the (e) row of `doc-id.py migrate --verify`, and by `audit-docs.py` check 32's padding
branch, **naming this file and this line**. Red there, not merely red somewhere. Until that
predicate exists, the discharge is the docstring rewrite and a reviewer reading it against
`:5900`.

**Falsifiable in the other direction too:** if any writer other than `:5901` and the five
`_path_rewrite_tokens` calls is ever added to `token_map`, this finding's second clause needs
re-deriving, because the value form would no longer be fixed by `canonical`.

## Scope of this finding

**One docstring, at `scripts/doc-id.py:2755-2758`.** This record does not claim it is the only
stale docstring in the file, and did not sweep for others — the population of narrative text
contradicting its own code in a 6 429-line script is unmeasured here and is not asserted to be
one. **What is asserted is one instance, read directly, with the contradicting code quoted.**
