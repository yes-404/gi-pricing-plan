# F101 — a guard disarmed by the very event it was written to survive

**Filed 2026-09-03 at `4b9117a` by the auditor.** Work item **W37-6**, phase 2. Raised during the
second measurement of NT-0019 §7 (`docs/audit/nt-0019-second-measurement-2026-09-03.md` §14.4),
and filed separately at the lead's request because the class outlives this migration.

**Id allocation.** Swept across **every** ref, not `origin/main` — a single-ref sweep cannot see
an id reserved on an open PR, which is the constraint F99's own allocation paragraph records and
then got wrong:

```bash
for r in $(git for-each-ref --format='%(refname)' refs/heads refs/remotes); do
  git ls-tree -r --name-only "$r" 2>/dev/null | grep -oE 'F[0-9]{1,3}\.md'
  git grep -hoE '\bF[0-9]{2,3}\b' "$r" -- docs/audit 2>/dev/null
done | grep -oE '[0-9]+' | sort -n -u | tail -1        # 100
```

Maximum is **100**. This record takes **F101**. `F98` appears as a token on two branches but no
`F98.md` exists on any ref; it is free, and its reclaim-or-tombstone is the maintainer's
(recorded in F99, not decided here).

## The defect

`scripts/_docverify.py` reads NT-0019 through a constant that is **deliberately the pre-migration
path**, so that the migration's own redirect table is followed rather than the new name guessed:

```python
#: The note's pre-migration path. Post-migration it is somewhere else, under a slug derived
#: from its *title*, not its old filename … It is followed through `docs/REDIRECTS.csv`, which
#: is the artifact the migration writes for exactly this purpose; guessing the new name
#: instead is how a row silently measures an empty file.
_NT0019_PATH: Final = "docs/notes/0019-one-id-per-document.md"
```

`_follow_redirect(tree, old_path)` tries the literal path first and falls back to
`docs/REDIRECTS.csv`. The fallback is the guard.

**The migration rewrites that constant.** Measured on a migrated snapshot of `4b9117a`:

| | `scripts/_docverify.py:1068` |
|---|---|
| un-migrated | `_NT0019_PATH: Final = "docs/notes/0019-one-id-per-document.md"` |
| migrated | `_NT0019_PATH: Final = "docs/rfcs/RFC-00216-one-id-per-governed-thing-one-sequence-integer-identity-a-self…"` |

It is a genuine path citation, so the citation rewriter rewrites it, **correctly** — the new name
it produces is the right one. Nothing breaks, and this record alleges no present incorrectness.

**But once the migration lands, `_follow_redirect`'s first branch resolves and the
`REDIRECTS.csv` lookup is never reached again.** The guard becomes dead code. From that point a
wrong value in the constant produces exactly the failure its own comment names — *"a row silently
measures an empty file"* — with the mechanism written to prevent it no longer in the path.

## Why it is a finding and not an observation

**A guard that stops guarding does so without anything going red.** The tests pass, the row
reports a number, and the number is even correct today. There is no failing case to notice,
because the disarming event and the correct-looking output are the same event.

It is also the second-order shape this work has now hit three times in one window, and the first
where the *remedy* is what gets disarmed:

| | what went green | why |
|---|---|---|
| A1 | §7(d)'s `F-W[0-9]` | corruption moved the tokens out of the predicate's reach |
| A5 / §6.1 | §7(d)'s `\.claude/notes/` | the predicate could never fire |
| **F101** | row (i)'s H-row count | **the guard against a silent empty read was removed by the migration it guards against** |

## Acceptance — the violation that must become detectable

*Violation: `_NT0019_PATH` resolves to a file the H-row scan reads as zero rows, and the run
reports a count rather than failing.*

Row (i) currently reports `45 H row(s) in §5`. **A non-zero assertion on that count is the
cheapest complete remedy** — it converts a silent empty read into a loud one and does not depend
on which branch of `_follow_redirect` resolved. It is the same rule the instrument's own `(h2)`
vacuity probe already applies to `audit-docs.py`: check the denominator, not only the count.

An alternative is to exempt the constant from the citation rewrite the way `was:` is exempted, so
the redirect stays live. **Neither is proposed here**; the choice is `executor-verify`'s.
