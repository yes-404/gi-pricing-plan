### 1.3 Part 2 — the field's own correctness, re-measured independently

**Method.** A fresh `migrate --verify` run against `43d86980` (this session's own, not
reused) produces three trees under the verify workdir: `control/` (the tree before
`migrate()` runs) and `migrated/` (after). `migrated/docs/REDIRECTS.csv` is the migration's
own authoritative old-path → new-path map, generated by the same run.

For every `*.md` file under `migrated/docs/`, `measure_was.py` (below) parses the front
matter exactly as `_docverify.was_field_line_numbers` does — the file must open with a `---`
block that closes, and a line inside it matching `^([A-Za-z_][A-Za-z0-9_]*):[ \t]?(.*)$` with
key `was` is the field — and, when the value is present and not `~`, checks it against
`REDIRECTS.csv`'s row for that document's own new path.

```python
#!/usr/bin/env python3
import csv, re
from pathlib import Path

MIGRATED = Path("migrated")   # relative to the --verify workdir
CONTROL = Path("control")
KEY_VALUE_RE = re.compile(r"^([A-Za-z_][A-Za-z0-9_]*):[ \t]?(.*)$")

def was_field_value(text):
    lines = text.splitlines()
    if not lines or lines[0] != "---":
        return None
    try:
        closing = lines.index("---", 1)
    except ValueError:
        return None
    for i in range(1, closing):
        m = KEY_VALUE_RE.match(lines[i])
        if m is not None and m.group(1) == "was":
            return m.group(2).strip()
    return None

redirects_path = MIGRATED / "docs" / "REDIRECTS.csv"
new_to_old = {}
with redirects_path.open(newline="") as f:
    for row in csv.DictReader(f):
        new_to_old[row["new_path"]] = row["old_path"]

docs = sorted(MIGRATED.glob("docs/**/*.md"))
total = correct = self_ref = never_existed = resolves_and_lies = names_nothing = 0
for p in docs:
    text = p.read_text(encoding="utf-8", errors="ignore")
    was_value = was_field_value(text)
    if was_value is None or was_value in ("", "~"):
        continue
    total += 1
    own_path = str(p.relative_to(MIGRATED))
    true_old = new_to_old.get(own_path)
    if true_old is not None and was_value == true_old:
        correct += 1
        continue
    if was_value == own_path:
        self_ref += 1
        continue
    exists_in_control = (CONTROL / was_value).exists()
    exists_in_migrated = (MIGRATED / was_value).exists()
    if not exists_in_control:
        never_existed += 1
        if exists_in_migrated:
            resolves_and_lies += 1
        else:
            names_nothing += 1
print(total, correct, self_ref, never_existed, resolves_and_lies, names_nothing)
```

### 1.4 What this does and does not settle

**Part 2's answer is a clean 367/367.** Read alone this looks like condition 2 is fully met.
It is not the whole picture, and this record does not claim it is:

- **The exemption's population is still what `(h2)`'s DISCLOSE calls OVER-EXEMPT**: 438
  documents in check 37's scope, 367 (84%) exempted by `was:`, leaving 71 shape-checked. That
  is a **separate, already-disclosed** question — whether a check that excuses 84% of its
  population is doing useful work — ruled non-fatal and disclosed under Ruling 105 D3. This
  record does not reopen it; it answers only "is the `was:` field itself trustworthy now",
  which is what Ruling 102 §5 asked re-measured.
- **This measures the field's consistency with the migration's own bookkeeping
  (`REDIRECTS.csv`), not an external ground truth independent of `doc-id.py` entirely.** The
  two spot checks in §1.3 are the mitigation: both were read directly off disk in `control/`
  and diffed against `migrated/`, without trusting any claim `doc-id.py` makes about itself.
  A full independent audit of all 367 against git history is out of this record's scope;
  what is in scope, and done, is showing the 367/367 figure is not an artifact of comparing
  one tool's output to itself with nothing external touched.
