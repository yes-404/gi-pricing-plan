## Goal

Close the `docs/`-scaffolding half of RFC-937 §5.2 — rewrite `docs/README.md` as the
map of the migrated tree, give `docs/research/` the README it never got, retire the last two
files under the dissolved audit directory as far as this slice's authority reaches, put the
id-and-gate conditions into both close checklists, and land the three rituals RFC-937 §6
adopted (fortnightly work-item status, dated per-phase freeze gates, the generated phase
report as the body of every `kind: phase` closure record) as *text in the artifacts that
enforce them* rather than as a second copy of the standard.

**Architecture:** Every edit in this slice is a document edit whose authority already exists —
RFC-937 §1.4, §1.10, §5.2 and §6, already accepted. Nothing here mints a requirement id, and
nothing here decides anything RFC-937 left open. Two edits touch derived artifacts and must
regenerate them in the same commit: `docs/process/delivery-process.core.json` carries a sha256
digest of `delivery-process.md`'s bytes (check 27) and `docs/INDEX.md` is generated by
`scripts/doc-index.py`. Two edits are *proposals* rather than changes, because
`docs/roadmap.md` is the lead's file under `.claude/roles/planner.md`.

**Tech Stack:** Markdown under `docs/`; `python3 scripts/audit-docs.py`,
`python3 scripts/doc-id.py check`, `python3 scripts/doc-index.py --check` / `--phase`; JSON for
the process core extract. No Python package code is written or changed by this slice — see
Decision point DP-1 for the one place that boundary is contested.

**Spec:** [`../rfcs/RFC-00937-one-id-per-governed-thing-one-sequence-integer-identity-a-self-describing-layout-and-roles-per-family.md`](../rfcs/RFC-00937-one-id-per-governed-thing-one-sequence-integer-identity-a-self-describing-layout-and-roles-per-family.md)
§1.4, §1.10, §5.2, §6 and §7 (i), lifted into
[`../process/document-ids.md`](../process/document-ids.md). The slice cut and its acceptance
are [`PL-00939-wk-697-one-id-per-governed-thing-map-plan.md`](PL-00939-wk-697-one-id-per-governed-thing-map-plan.md)
`:815-838` (the slice section) and `:371-383` (the sequencing table). Executors read both.

## Global Constraints

Copied verbatim from the sources named, because a paraphrase of a constraint is not the
constraint.

- **Requirement IDs and section numbers are permanent** — "never renumber; append, mark
  superseded, or leave a tombstone" (`CLAUDE.md` §0). This slice mints no requirement id and
  renumbers none.
- **`docs/contracts/` is generated and never hand-edited** (`CLAUDE.md` §2). Not touched here.
- **A filed plan under `docs/plans/` is frozen at its date** (`CLAUDE.md` §2). This plan is
  filed `draft`; it freezes when it reaches `active`.
- **Counts and status that change are not written in `CLAUDE.md`**, and `docs/roadmap.md` holds
  workstream and component status (`CLAUDE.md` §0). The corollary this slice is most likely to
  break: **`docs/README.md` must carry nothing that goes stale** (map plan `:819`) — no counts,
  no enumerations a generated artifact already holds, no status.
- **The markdown is authoritative; the extract is derived** — "on any disagreement the markdown
  wins and the extract is wrong by definition"
  ([`../process/delivery-process.md`](../process/delivery-process.md) §10).
- **`docs/roadmap.md` is the lead's file.** "A roadmap-row correction or other `docs/` edit
  surfaced inside a plan review is a proposal in the review document, applied by the lead or
  decision-maker" (`.claude/roles/planner.md`). Tasks 8a and 8b are proposals for that reason.
- **Evidence is write-once**, and "a correction after the fact is dated and says so"
  ([`../closures/README.md`](../closures/README.md)). This is why no task in this plan rewrites
  a filed `CR-`, `FD-`, `RL-`, `LG-` or frozen `PL-` record, and why DP-1 exists at all.
- **Every number in this plan is pasted from a command or a named artifact at
  `d63f765085fe6eb1c594177c5779ecfc3caf7ae8`** (`origin/main` at drafting), and an executor
  re-derives rather than quotes it.

### 1.3 The three rituals — what "landing" one means here

RFC-937 §6, verbatim: *"Fortnightly `WK-` status entries via `reporter-cycle`; dated plan/code/
docs freeze gates per phase checked by `phase-close.md`; the generated phase report as the body
of every `CR- kind: phase`; PR titles name the slice."*

A ritual is landed when the artifact that **enforces** it says so — not when a second copy of
§1.10 exists somewhere. Concretely:

- **(a) Fortnightly work-item status.** Enforced by `reporter-cycle` (W37-7's skill) driving
  entries; this slice adds the obligation to `delivery-process.md` §13's monitoring loop, which
  is where the reporter's duties already live, and names the skill as the mechanism.
- **(b) Dated freeze gates.** Enforced by `phase-close.md` checking them; this slice adds the
  *check* to `phase-close.md` (Task 5) and the *declaration* requirement to
  `delivery-process.md` (Task 6). The per-phase **dates** are a roadmap edit and therefore a
  proposal (Task 8a).
- **(c) Generated phase report.** Enforced by `docs/_templates/CR.md` naming
  `doc-index.py --phase` as the body of a `kind: phase` record (Task 7), and by `phase-close.md`
  naming the same command (Task 5). The generator already exists: `scripts/doc-index.py:1167`
  registers `--phase`, and `phase_report()` is at `:981`.

**A second trap, found by this plan reding its own gate a second time.** `_FENCE_RE` is
`^\s{0,3}(` followed by the two markers, so **prose that begins a line with a fence marker
opens a phantom fence** and inverts the parity of every fence after it. Writing this very
paragraph broke §7.1's exhibit that way. Never start a line with a fence marker in prose;
keep it mid-line, or name it as `_FENCE_RE`'s alternatives rather than reproducing it.

An executor editing this plan, or writing any new document in this slice, inherits that rule.

```bash
python3 scripts/audit-docs.py 2>&1 | sed -n '/^FAILED/,$p'
```
