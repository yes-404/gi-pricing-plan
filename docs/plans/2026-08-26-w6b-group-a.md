## Findings (verified 2026-08-26 against origin/main 1f691de)

**F1 (W6b-17). The companion pair has no block and no writer.** `GlmSpec.approximates_model_id: UUID | None` is a bare id (`model_schema/modelling.py:1040`), and `02` §4.4's note (lines 801-814) calls the bare form "a deliberate divergence from `interval_for`" — the sentence this slice amends. `IntervalFor` (`:1261`) is the block precedent: `model_id` + `model_version`, "the id is what the lookup uses; the version is what a human reads". The `spec_hash` payload is the whole spec (`backend/src/app/platform/modelling.py:160-170`), so a companion field joins the digest by construction and the version tag must bump. The transparency Job's `approximation_spec` (`packages/pricing-core/src/pricing_core/modelling/transparency.py:94`) sets `approximates_model_id=source_model_id`; its caller (`backend/src/app/worker/model_handlers.py:963-971`) already asserts `source_slug` and `source_version` in scope. `reserve_model` (`backend/src/app/platform/modelling.py:340`) receives the source Model from `_refuse_mismatched_approximation`, which compares three fields (`dataset_version_id`, `split_ref`, `factors`) where the sibling `interval_for` guard compares four and leads with the slug — the OQ-MODEL-34 evidence records this asymmetry. `ModelSpecCommon` is frozen; the stored spec is the caller's verbatim.

**F2 (W6b-18). The emission is lossy in three independent ways, and five sites emit no keys at all.** `_sample` (`packages/pricing-core/src/pricing_core/data/validate.py:128`) pipe-joins key values with no escaping, renders `None` as `""`, and drops the column names. Thirteen call sites feed `offending_sample`; five emit raw values or column names rather than keyed rows — `_dtype_match` (`:278`, column names), `_date_parsed` (`:309`, column names), `_no_unexpected_columns` (`:375`, column names), the referential check (`:517`, unresolved values), `_code_list` (`:646`, new codes). The model types it `tuple[str, ...]` (`model_schema/validation.py:509`); the authored contract declares a bare `{"type": "object"}` item (`docs/contracts/schemas/validation-report.schema.json:51`) that constrains nothing. The comparison pin is live at `backend/tests/test_contracts.py:1002` (`validation-report` → `results.[].offending_sample.[]`) with the reasoning recorded at `:963-984`. `01` §4.6's only example prints `"offending_sample": []` (`docs/specs/01-data-management.md:538`). The pin note measures the test surface: 13 assertions across `test_validate.py`, `test_catalogue.py` and `test_api_datasets.py`.

**F3 (W6b-19). The model lags its contract on 17 paths, and the envelope fields have no row columns.** `DatasetVersion` (`model_schema/datasets.py:277`) carries 5 of the envelope's 14 flat fields (`id`, `workspace_id`, `version`, `status`, `created_at`) and lacks `slug`, `description`, `created_by`, `updated_at`, `archived_at`, `parent_id`, `labels`, `schema_version`, `currency`; it holds `period_from`/`period_to` scalars, `source_fingerprint: dict[str, str] | None` and `derived_from: dict[str, object] | None` where the authored contract (`docs/contracts/schemas/dataset-version.schema.json`) declares `period_covered.{from,to}`, `source_fingerprint.{kind,value,extracted_at}` and `derived_from.{parent_version_id,operation,params}` and composes the envelope by `allOf`. The backend `_version_schema` (`backend/src/app/api/datasets.py:641`) maps the row with the old scalar shapes; `DatasetVersionRow` (`backend/src/app/db/models.py:759`) has no envelope columns; `new_version` (`backend/src/app/platform/datasets.py:409`) already receives `actor: Principal` (the `created_by` source) and both call sites pass a principal (`data/ingestion.py:182`, `platform/datasets.py:818`). The derive path already stores `derived_from` with the contract's exact keys. The audit chain (`db/models.py:164`) stores `actor` as JSONB with an `id` key (`model_schema/jobs.py:116`, `Principal`) and `entity_ref = "dataset_version:{slug}@{version}"` — the `created_by` backfill. `Dataset.slug` shares the 63-character pattern (`datasets.py:160`), so a version slug copied from the dataset always validates. The comparison test compares only paths present on both sides (`test_contracts.py:1096-1098`), so container nullability is structural and skipped; the remaining one-sided path after this slice (`tables.[].source_names`) is tolerated by design. **OQ-OVR-16's pin fires here**: its condition to reopen is "the first artifact that persists an envelope", and this slice makes `DatasetVersion` exactly that — the pin entry (`test_contracts.py:1003`, `artifact-envelope` → `updated_at`) resolves per the ruling's option (a): `envelope.py:38` drops `| None`, the authored contract, `00` §4.3 and the twelve composers already read non-null, and the one construction at `packages/model-schema/tests/test_refs.py:40` gains a value.

**F4 (W6b-19, the sequencing premise — VACATED, filed per slice-map P12).** OQ-DATA-13's decision text sequences W6b-19 with W6b-12 on the premise that "the lineage handler types against it". Verified false against merged main: the lineage handler types against `DatasetVersionRow` — `lineage_of` (`backend/src/app/platform/datasets.py:855`) returns `DatasetLineage` built from row data and never constructs the schema `DatasetVersion`.
