# ADR-8449 — Project management moves to GitHub, with a slim CLAUDE.md and frozen record families

- **Status:** draft
- **Deciders:** the maintainer

## Context

A second person, the collaborator, joins, and a contributor may follow. The project then runs with
two people. Its management records (plans, ledgers, rulings, closures, findings, the
roadmap) are about 320,000 lines against about 10,000 lines of specification, and 50 of
the 63 merges on `main` since 1 Oct are titled docs. The user decided on 13 Nov 2026 to
run the project through GitHub issues and milestones instead. Options and research are in
the consultation notes the user's decisions came from; the decisions themselves are
quoted below, verbatim except the bracketed role replacements, in the Appendix.

## Decision

We adopt the new frame the user decided on 13 Nov 2026 (Appendix: items 1–31 and the later decisions):

- GitHub milestones (named by version, pooled into one, `v0.3.0`, for now) carry the plan,
  and issues carry the work. One issue per Work; a contributor
  delivers a Work as one pull request built as a reviewed series of commits, squash-merged.
  The rule binds contributors only.
- Review is by risk in four tiers, with six high-risk areas and a three-working-day window.
- Findings are public by default; a possible wrong price, data leak or security defect is a
  private advisory.
- Records that stay as files: specifications, workflows, contracts, decision records in
  `docs/adrs/`, acceptance lines, the requirement-to-test trace and process rules.
- The old record families (plans, ledgers, rulings, closures, findings, RFCs, the old
  roadmap) are frozen, not deleted.
- `CLAUDE.md` is replaced by the slim version. The old section numbers are retired: **a
  citation of an old section number refers to the `CLAUDE.md` in git history before this
  record's merge.** The slim file's History section points here. This is the maintainer's
  amendment of `CLAUDE.md`.
- Decision records live in the existing `docs/adrs/`, not in a new `docs/decisions/`.

The order to migrate was given by the user on 13 Nov 2026 (22:00 GMT), verbatim: "the
artifact changes accepted, plz instruct the lead to start migration to the new frame at the
earliest available stage. and defer the closure after the migration complete."

## Consequences

- Good: records stop crowding out building; ownership of each open item is a GitHub field
  and a weekly job, not a per-document discipline.
- Bad: issue text is editable and unreviewed, so a decision can stay buried in a thread
  (safeguards 23–26 answer this). Checks that guarded record families are retired after the
  maintainer rules on the classification table; spec guards stay. Old citations resolve
  only through git history.
- Follow-up: the freeze check, the check classification table, the stage-4 migration of
  open findings, open questions and the current milestone's Works, branch protection.

## Appendix — the process pages: what survives, what is frozen, and the residue ruling

`docs/process/delivery-process.md` and `docs/process/document-ids.md` (and the extract
`delivery-process.core.json`) are retired by the new frame and are in the freeze constant
(`scripts/_frozen.py`), so this change does not edit them. An earlier draft of this change had rewritten legacy forms in them to zero a count;
that was reverted (the pages are restored to their `origin/main` content), because an old
document is never rewritten to make a number zero. Nothing kept cites a section of them as a
live rule. What survives of them lives in
`CONTRIBUTING.md` and in the kept checks, not in those pages:

- Survives (into CONTRIBUTING): delivery-process §2 (the human checkpoint: nobody merges their
  own PR) and §3 (roles, reduced to the maintainer and the collaborator); document-ids §1.1
  rules 1 and 2 (one integer sequence for every id; citations write the integer, never padding)
  and §1.7 (an id is taken at the merge turn, `doc-id.py next`); requirement ids stay permanent
  by CLAUDE.md and check 2/3. Uniqueness stays checked by checks
  2, 3 and 31.
- Frozen with the pages (read as history, never extended): delivery-process §4-§8, §9-§14 (the
  hierarchy, per-layer flow, slice layer, escalation guards, parallelism, the findings register,
  required artifacts, plan and audit-record obligations, the monitoring loop, the adoption
  workflow) and §15; §11a (`migrate --verify`, retired); document-ids §1.2-§1.6, §1.8-§1.13
  (the record families, layout, roles per family, GitHub alignment, rituals, audit, widening).
- Kept and still governed: the other pages under `docs/process/` (agent settings, the process
  backlog, the retrofit-impossible list, the security posture and the checklists).

The residue ruling (the maintainer's entry of 2026-11-13 23:03:51 GMT): checks 30 and 35
(document headers) and 36 (legacy id forms) apply to `docs/specs`, `docs/adrs`,
`docs/workflows` and the kept process pages, and to nothing else (`_frozen.is_governed`).
Inside those families a violation the change's own diff introduces fails; the count that
pre-exists is printed by each check on every run and can only go down. No old document is
rewritten to make a number zero. Check 32 reports its one pre-existing unresolved citation
(a skill's prose) the same way. The range is `scripts/freeze-check.py`'s `changed_paths`,
imported, not a second implementation.
